who i amabout me

Good interfaces feel obvious. Getting there is the work: interviews, messy sketches, three wrong flows and one right one.

I'm a UX and UI designer working with small teams and founders. I like the unglamorous parts: reading support tickets, watching someone try the prototype, deleting the screen nobody needed.

My designs ship as working front ends, so what you approve in Figma is what lands in the browser. Most projects run four to eight weeks, with a fixed scope and a short demo every Friday.

work process

  1. design

    Interviews, flows and wireframes first, then the visual layer. You review clickable prototypes, not slide decks.

    • research
    • wireframes
    • UI kit

  2. development

    Approved screens become semantic HTML and CSS with no builder bloat, responsive from a phone to a wide desktop.

    • HTML / CSS
    • WordPress
    • components

  3. testing

    Real devices, real people and a checklist for accessibility, speed and forms, so surprises happen before launch.

    • usability
    • a11y
    • speed

  4. launch

    Go-live support, a hand-over session and a style guide, then thirty days of fixes included in the price.

    • hand-over
    • style guide
    • support
